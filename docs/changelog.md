### Differences from the spec

The docs win. Each item says what the build follows and which spec section should change.

1. **Data folder lifetime and place (check 1).** Docs: deleted only when the plugin leaves its last scope (and kept in a few edge cases); the whole plugins root moves with `CLAUDE_CODE_PLUGIN_CACHE_DIR`. Build: no change to sections 6 or 9. Wording fix in 9.6 ("Either way, inside the config folder" becomes "in Claude Code's plugin data folder, normally inside the config folder"), section 11 items 1 and 7, and 12.3.
2. **Copied skills (fact 3).** Docs: personal skills still get `${CLAUDE_SKILL_DIR}` and `${CLAUDE_PROJECT_DIR}` substituted; only the plugin variables stay raw. Build: the 6.6 rule "no skill text uses a plugin path variable" still holds. Fix the wording of fact 3 in 3.1.
3. **Hook input fields (fact 5).** Docs: `effort` is not sent to `UserPromptSubmit` or `SessionStart`; `permission_mode` is not sent to every event. Build: the core scripts do not use either. Fix fact 5 in 3.1.
4. **`engines` (fact 6, check 16).** Docs: an object with a `claude-code` semver range, accepted from v2.1.323; versions 2.0.15 to 2.1.75 refuse the manifest. Build: add `engines` only if the tested version is 2.1.323 or later and the README states that floor; otherwise leave it out. Fix fact 6 and the `plugin.json` row in 14.3.
5. **Option `title` is required (fact 7).** Build: every option in 6.2 and 9.13 gets a `title`, or `validate` fails. Using `options` for `matching` needs v2.1.271 or later; the build either relies on that or validates the value in code. Fix fact 7 and the option tables.
6. **`node:sqlite` on Node 24 (fact 17).** Docs: release candidate on current 24.x and 26.x; still active development on 22.x. Build: the pure-JavaScript index stays, because Node 22 is the minimum. Fix fact 17 and 7.4 a.
7. **Built-in helper models (check 13).** Docs: `CLAUDE_CODE_SUBAGENT_MODEL` alone does not move Explore or Plan; the force switch is `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`; under a Fable main chat, Explore runs on the `opus` model; `/tasks` shows model and effort. Build: the rule text names these. Fix 5.2 points 9, 11 and 12.
8. **Model aliases (check 14).** Docs: besides `haiku`, `sonnet` and `opus` there is `fable` (for the hardest, longest tasks) and `best` (same as `opus`). Build: the tier table keeps top = `opus` unless the owner decides otherwise, and mentions `fable` as an optional higher choice. Fix 5.3.
9. **Vendor token rules (check 21).** Docs: no vendor publishes a minimum length; `sk-svcacct-` is not on OpenAI's own pages; Stripe also issues `sk_org_` keys. Build: set a documented minimum per prefix in the scan rules and test both sides of it; keep `sk-svcacct-` (removing a prefix needs a written reason, and this is not one); add `sk_org_`. Fix SR-13 a and f.
10. **Caching list (section 8.2).** Docs list more cache-rebuild causes than the spec. ### B5 search engine, phase 1

Built: `walker`, `ignore`, `floor`, `scan`, `chunker`, `markers`, `tokenize`, `index`, `rank` (BM25 part), `store` and `fsx` under `src/search/server/`, with their tests under `tests/search/`. Decisions where the spec leaves a choice:

- **Design changes (spec first, Appendix C row "B5 search engine, phase 1"):** ignore rules also come from the folders above a root that sits below its git work tree top, plus that top's `info/exclude`; an unsafe or unparseable global excludes file is skipped and counted (`global_excludes_unread`) instead of turning search off; `*.env` joins the SR-9 e type list.
- **Seams (check 5, `floor.cjs`):** `isUnsetValue` treats an empty value and the raw `${user_config.KEY}` text as "never set" (the default applies); `splitListOption` accepts an array, a JSON-array string, or one string split on commas and new lines. No B5 code depends on check 1 or check 6: the store takes the data root from its caller (install mode is B7), and the ignore reader finds the work tree top itself.
- **Ranking:** BM25F. Each field is length-normalised on its own (b 0.75), weighted (heading 2, body 1, file name 1.5 at the broader level only), summed, saturated once (k1 1.2) and multiplied by a non-negative IDF, `ln(1 + (N - df + 0.5) / (df + 0.5))`. A document scores the sum over query words of each word's best expansion. Superseded (and shown cancelled) text is multiplied by `RETIRED_FACTOR` 0.5, on top of the flag tie-break. Hook points for B6: `expand(word)` and `bonus(doc)` options, and the file-name field switched on by `matching: "broad"`.
- **Body field** excludes a chunk's own heading line, so a heading word counts in the heading field only.
- **Words:** positions count every word (kept or dropped). Combining marks stay inside a word. A word over 64 code points is dropped. Words are NFC-normalised for the index only (stored text is never changed). The acronym rule needs at least one upper-case letter. Repeated query words are used once; the 32-word cap applies to kept words.
- **Stop words:** the project's own list of about 120 common English words, fixed in `tokenize.cjs`; `tokenizer_version` is a hash of the word rules and the list.
- **Chunking:** `.md`, `.markdown` and `.mdx` are cut at ATX headings levels 1 to 4 outside fenced code; other allowed types are plain text. Setext headings do not cut. Front matter stays in the first chunk and is never read as a heading. The heading trail includes the chunk's own heading.
- **Marks:** mark words are matched in upper case only; an optional `(who)` part is accepted and thrown away; a backticked path is accepted. "First line under a heading" is the first non-blank line. A full mark (superseded or cancelled) also covers the sections nested under it. The title block is the file's true first section (section 0, before any scan drop) when it is the preamble or a level-1 heading. A successor is looked up as a project-relative path first, then relative to the marked file's folder.
- **Scan:** only SR-13 b secret hits count toward the two-hits rule; hidden HTML, contact and never-term drops do not. Setting labels need a word edge on both sides (`_` and a lower-to-upper change count) and a value of 8 or more characters; Authorization values need 8 or more. Only a whole placeholder shape is exempt (see the review fixes below; this replaced a "starts with `<`, `$`, `%`, `{` or `*`" rule). A JWT's first two parts are each at least 10 characters including `eyJ`. One variation selector is allowed after any emoji character (so keycaps pass). Phone numbers: an international form starting `+` with 8 to 15 digits, or a grouped 3-3-4 form. Literal pre-checks skip a pattern that cannot match.
- **Hidden HTML:** `<!--` anywhere, a reference line pointing at `#` or `<>`, and a tag with a `hidden` or `style` attribute.
- **Store:** unchanged means the same size and the same modified time in nanoseconds (manifest field `mtimeNs`). A file not reached because a size cap stopped the build is not kept from an earlier run, so every kept file was re-tested this run. A corrupt index is announced like a version change (named error until rebuilt, then one notice). Nothing is written when a refresh changed nothing. The lock also holds a random nonce beside the process id and start time; its modified time is refreshed between files. Unprocessed files past a cap are counted under `size_cap`, so succeeded, failed and skipped always add up to the files visited.

### B6 search engine, phase 2

Built: `stem.cjs` (new), and phase 2 in `rank.cjs`, `index.cjs`, `tokenize.cjs` and `store.cjs`: word families, typed trailing wildcard, automatic prefix, near spellings, synonyms, the all-words and closeness bonuses, the file-name field, and the `matching`, `word_families` and `synonyms` options. Decisions where the spec leaves a choice:

- **Design changes (spec first, Appendix C row "B6 search engine, phase 2"):** family expansions count toward the 20-term cap, and the cap takes expansions in the fixed order family, synonym, prefix, fuzzy (each kind in sorted order; synonyms in entry order). Once one expansion does not fit, nothing more is added and the result carries the note `expansion_capped`. On the file side the acronym rule for families is judged per index term: a term joins its family when at least one chunk holds it in a non-acronym form (the index keeps one lower-cased term for `TESTS` and `tests`).
- **Seam (check 5):** synonyms are parsed only through `floor.splitListOption` (array, JSON-array text, or one string split on commas and new lines), marked `// SEAM(check 5):` in `rank.cjs`. No second parser. `matching` and `word_families` are plain strings checked in code; a raw `${user_config.KEY}` text is simply not a valid value and falls to the default.
- **Stemmer:** the project's own light rules (plurals; `ed`, `ied`, `eed`, `ing` with the usual `e` and double-letter fix-ups; a final `e` dropped when 4 or more letters stay); a stem is never shorter than 3 letters. The family map (family key to terms) is kept up to date at index time, in memory only, as words come and go; the index on disk stores raw words, so `word_families` needs no rebuild and `tokenizer_version` is unchanged. Known misses are accepted (for example `used` stays `used`).
- **Where options act:** `matching`, `word_families` and `synonyms` act at query time only, are not in the index options hash, and never trigger a rebuild. `rank()` defaults to `broad` when `matching` is missing or not `exact`/`broad` (case and spaces ignored). The store reads them from its options once and a call may override them; `status` shows `matching`, `wordFamilies` and `queryCounts.bad_synonym` (a count only).
- **Wildcards (T-17):** a typed `*` counts only when exactly one `*` follows a word and the next character is the end or a separator; a middle `*` and `**` are separators (this replaced the B5 parse that made `roll*back` a wildcard on `roll`). A stem under 3 characters gets no look-up and the note `wildcard_too_short`; over 200 terms → the first 200 in sorted order and `wildcard_capped`. A typed wildcard replaces the automatic prefix for that word; families, synonyms and near spellings still apply under the 20 cap. At the exact level a `*` is a separator and the result carries `wildcard_ignored`.
- **Near spellings:** Levenshtein distance (insert, delete, change one letter), counted in code points, searched in the length buckets within the allowed distance. The scan checks the query budget every 256 terms and returns `partial` when it runs out.
- **Synonyms:** entry words go through the same word rules as the index (lower-cased; stop words and 1-character words dropped); a side that keeps no word is a bad entry. The term must match consecutive query words after the word rules; its alternatives attach to the term's first word, and wherever an alternative matches, every word of the term counts as matched (for the all-words and closeness bonuses). Alternatives are matched exactly (no family, prefix or near-spelling expansion of an alternative). A multi-word alternative scores the mean of its words' scores and matches only where its words sit within 8 positions in the body, or all in the heading, or all in the file name. Repeated terms merge; an alternative equal to its term is dropped. The 500-entry limit counts list positions.
- **Bonuses:** "within N positions" means the smallest span holding one occurrence of each matched word is at most N positions (positions 0 and 7 are within 8). A word's occurrences are those of every expansion that matched it. When every matched word appears in the heading, the chunk counts as within 8. A matched word with no body occurrence (and not all in the heading) gives no closeness bonus. If the query budget runs out while bonuses are worked out, the rest are left out and the result is `partial`.
- **Labels and notes:** `matched_by` lists the label of the best-scoring expansion of each matched word, sorted; a result always has at least one. The result also carries `matching` and `notes` (fixed codes only, never query text).
- **Golden set:** 40 synthetic notes and 20 questions in one fixture file, run through the real store. Phase 1 ranks each of the 10 exact-word questions' files first; phase 2 ranks all 20 first, including the plural, family, wildcard, prefix, typo and synonym ones, which phase 1 does not have in its top 5, and labels each with the expected match kind. A fixture folder named `build/` was renamed, because the floor skips build folders.
